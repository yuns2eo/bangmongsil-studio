# bangmongsil-studio

펫프렌즈 마스코트 **몽실이(MONGSIL)** 와 **방실이(BANGSIL)** 이미지를 **언제 생성하든 같은 캐릭터로** 유지하기 위한 작업 기준 저장소입니다.

이 README는 AI(Claude / ChatGPT 등)가 읽는 작업 지침서입니다. 캐릭터 이미지 요청을 받으면 아래 순서를 그대로 따르세요.

---

## 두 캐릭터를 섞지 않는 것이 이 저장소의 핵심

몽실이와 방실이는 **몸은 거의 같고 얼굴과 포인트 컬러가 정반대**입니다.

| | 몽실이 | 방실이 |
|---|---|---|
| 포인트 컬러 | `#FFCDB4` | `#FFCBD1` |
| 갈색 `#B79571` | 머리 & 귀 물결, 팔 하트, 꼬리 | **없음** |
| 귀 | 짧고 둥근 삼각 | 길고 뾰족한 삼각 |
| 입주변 | 흰 덩이 2개 돌출 | 평평함 |
| 다문 입 | 입선 **없음** | W 입선 **있음** |
| 꼬리 | 갈색 | 몸색 |

그래서 **한 프롬프트에는 한 캐릭터의 락 파일과 장면 블록만 넣습니다.** 둘을 같이 넣으면 생성 모델이 구분하지 못하고 섞습니다. 투샷은 각 락 파일 10번을 따릅니다.

---

## 저장소 구조

```
CLAUDE.md                        Claude Code용 실행 규칙 (폴더를 열면 자동 로드)
.mcp.json                        Higgsfield MCP 연결 설정
characters/
  mongsil/
    MONGSIL_Character_Lock.md    몽실이 정체성 락 (몽실 요청에 항상 적용)
    scene-blocks.md              몽실이 Subject & Critical conditions & Negative
    references/3d/               Front / Left_3Q / Left_Profile / Back
                                 Paw_Front / Paw_Hind / Tongue / Sit / Run   (9장)
  bangsil/
    BANGSIL_Character_Lock.md    방실이 정체성 락 (방실 요청에 항상 적용)
    scene-blocks.md              방실이 Subject & Critical conditions & Negative
    references/3d/               Front / Left_3Q / Left_Profile / Back
                                 Smile / Sit / Run / Wave                    (8장)
styles/
  3D_Felt.md                     3D 펠트 렌더 스타일 (두 캐릭터 공통)
templates/
  scene.md                       장면 프롬프트 골격 & 워크플로 (두 캐릭터 공통)
prompts/
  README.md                      생성 기록 형식 & 상태 값
  YYYY-MM-DD-슬러그.md            실제 생성 기록 (승인 & 미확인 & 실패)
```

Claude Code에서는 `CLAUDE.md`가 Element 선택, 생성 설정, 기록 방법까지 정합니다. 그 외 AI는 이 README 순서대로 작업하고 `templates/scene.md` 골격으로 프롬프트를 씁니다.

## 작업 순서

### 1. 캐릭터 판별 후 해당 락 로드 (필수, 예외 없음)

요청이 몽실이인지 방실이인지 먼저 정하고, **그 캐릭터의 락 파일 하나만** 읽습니다. 의상, 소품, 계절, 장소, 장르와 무관하게 항상 적용됩니다.

요청에 캐릭터가 명확하지 않으면 **임의로 고르지 말고 묻습니다.**

### 2. 스타일 파일 판단

| 요청 | 적용 파일 |
|---|---|
| 3D, 입체, 피규어, 인형, 별도 언급 없음 | `styles/3D_Felt.md` |
| 2D, 일러스트, 스티커, 이모티콘, 플랫 | 아직 없음. 사용자에게 먼저 물어볼 것 |

### 3. 레퍼런스 이미지 첨부

요청한 카메라 앵글에 맞는 이미지를 **해당 캐릭터 폴더에서만** 가져옵니다. 다른 캐릭터의 레퍼런스를 섞어 넣지 않습니다.

| 앵글 | 몽실이 | 방실이 |
|---|---|---|
| 정면 | `Front.png` | `Front.png` |
| 45도 | `Left_3Q.png` | `Left_3Q.png` |
| 측면 | `Left_Profile.png` | `Left_Profile.png` |
| 뒷모습 | `Back.png` | `Back.png` |
| 걷기 & 달리기 | `Run.png` | `Run.png` |
| 앉기 | `Sit.png` | `Sit.png` |
| 입 벌린 표정 | `Tongue.png` | `Smile.png` |
| 발바닥이 보이는 장면 | `Paw_Hind.png` 추가 | `Sit.png` 참고 |
| 손바닥이 보이는 장면 | `Paw_Front.png` 추가 | **레퍼런스 없음** — 뒷발 패드 구성을 쓰고 미검증임을 알릴 것 |
| 손 흔들기 | — | `Wave.png` (손등이 보이는 포즈) |

- 앵글이 명시되지 않았으면 `Front.png` + `Left_3Q.png` 두 장을 첨부합니다.
- 표정 & 포즈 레퍼런스는 비슷한 것을 요청할 때만 추가합니다.
- 레퍼런스는 몽실이 9장이 2026-11-09, 방실이 8장이 같은 날 등록된 세트입니다. 수치 기준은 모두 각 락 파일에 측정값으로 들어가 있습니다.

### 4. 씬 요소 작성

`templates/scene.md` 골격을 쓰고, `## Subject` & `## Critical conditions` & `## Negative`는 해당 캐릭터의 `scene-blocks.md`에서 그대로 가져옵니다.

락 파일이 고정하지 않는 부분만 자유롭게 구성합니다. 의상, 소품, 포즈, 행동, 표정, 장소, 계절, 날씨, 조명, 분위기, 카메라 거리 & 앵글.

## 생성 도구

- 이미지 생성 모델은 **GPT Image 2**를 사용합니다. Nano Banana 계열은 원본과 다르게 나와서 쓰지 않습니다.
- Higgsfield 캐릭터 Element는 `CLAUDE.md`의 캐릭터 표를 따릅니다.
  - 생성 시 실제로 주입되는 이미지는 Element의 **첫 장(정면)뿐**입니다. (2026-10-19 생성 기록으로 확인)
  - 정면이 아닌 구도는 해당 캐릭터 폴더의 레퍼런스를 참조 이미지로 함께 첨부합니다.
  - 캐릭터 Element는 한 번에 1개만 씁니다.
- 기본 생성은 비용 최소화 설정(low & 1K & 1장)입니다. 고화질은 사용자가 명시적으로 요청할 때만 씁니다. 자세한 규칙은 `CLAUDE.md` 기본 이미지 생성 설정을 따릅니다.

## 우선순위

충돌이 생기면 위쪽이 항상 이깁니다.

1. 해당 캐릭터의 승인된 3D 레퍼런스 이미지
2. 해당 캐릭터의 락 파일
3. `styles/3D_Felt.md`
4. `templates/scene.md`
5. 사용자의 씬 요청 (환경, 조명, 분위기 등)

씬 요청이 캐릭터 정체성과 충돌하면 **정체성을 지키고**, 무엇을 조정했는지 사용자에게 알립니다.
레퍼런스에서 보이지 않는 디테일은 추측해서 채우지 않고, 가장 가까운 레퍼런스를 따르거나 사용자에게 확인합니다.

## 생성 후 검수

결과를 넘기기 전에 가장 가까운 레퍼런스와 비교하고, **해당 캐릭터 락 파일 9번 전 항목**을 하나씩 확인합니다. 하나라도 걸리면 다시 생성합니다.

두 캐릭터 공통으로 특히 자주 걸리는 것들입니다.

- 측면에서 아래 얼굴이 뾰족한 세모가 됨
- 머리가 작아지거나 세로로 긴 타원이 됨 (전신 높이의 약 절반, 가로로 넓은 타원이어야 함)
- 배 패치가 길쭉한 타원이 됨 (가운데의 **원**이어야 함)
- 수염이 얼굴에 그려진 선처럼 박혀 있음, 또는 한쪽에 2가닥이 아님
- 이빨이 보임
- 몸이 날씬해지거나 팔다리가 길어짐, 팔을 들 때 팔이 얼굴에 붙음
- 발가락 패드가 3개가 아님
- 꼬리가 납작해지거나 안쪽 가장자리에 혹이 생김 (세워진 1.3~1.5 : 1, 바깥쪽에만 3덩이)
- 옷이나 소품에 배 패치가 다 가려짐
- 앞에 있는 책상 & 바구니 위에 상반신이 올려진 것처럼 보임 (물체 뒤에 서 있어야 함)

**섞임 검사는 따로 봅니다.**

- 몽실이에 `#FFCBD1`, 뾰족한 긴 귀, 평평한 얼굴, W 입선이 나타남
- 방실이에 갈색이 조금이라도 나타남, 돌출 입주변이 생김, 입선이 사라짐, `#FFCDB4`가 쓰임

섞임이 보이면 보정하지 말고 다시 생성합니다. 원인은 거의 항상 다른 캐릭터의 문장이나 레퍼런스가 프롬프트에 들어간 것입니다.

## 단계별 생성

장면은 한 번에 만들지 않습니다. 의상 & 소품만 입힌 캐릭터(단색 배경)로 캐릭터부터 확인하고, 그다음 장면 & 행동을 더하고, 마지막에 누끼 & 배경을 나눠 디자인 툴에서 합성합니다. 문구와 로고는 생성하지 않고 디자인 툴에서 얹습니다. 자세한 기준은 `templates/scene.md` 7번을 따릅니다.

같은 결과를 계속 이어서 편집하지 않습니다. 편집은 1회까지만 하고, 그 뒤로는 원본 레퍼런스로 새로 생성합니다.

---

## 금지 사항

- 한 프롬프트에 두 캐릭터의 락 & 장면 블록 & 레퍼런스를 같이 넣지 않습니다. 투샷은 각 락 10번을 따릅니다.
- 락 파일 내용을 임의로 해석, 완화, 생략하지 않습니다.
- 씬 분위기에 맞춰 캐릭터를 리디자인하지 않습니다. 배경이 바뀌어도 같은 캐릭터입니다.
- 무늬 위치를 뒤집지 않습니다. 몽실이의 갈색 물결 무늬는 몽실 기준 **왼쪽** 귀 & 머리(정면에서 화면 오른쪽)에 있고, 팔 하트와 꼬리도 같은 쪽입니다. 방실이의 꼬리도 같은 쪽입니다.
- 락 파일(`characters/`), 스타일 파일(`styles/`), 레퍼런스는 사용자가 명시적으로 요청할 때만 수정합니다.

## 확장 방법

### 새 스타일 추가 (예: 2D 플랫)

1. `styles/{이름}.md` 생성
   - 상단에 "해당 캐릭터 락을 먼저 읽을 것, 락이 상위 우선순위" 명시
   - 재질, 선, 채색, 조명 같은 렌더 방식만 정의. 형태, 얼굴, 색, 무늬는 건드리지 않음
2. `characters/{캐릭터}/references/{스타일}/`에 레퍼런스 이미지 추가
3. 이 README의 구조와 스타일 판단 표에 항목 추가

### 새 캐릭터 추가

1. `characters/{이름}/` 폴더에 락, `scene-blocks.md`, `references/3d/` 생성
2. 락은 레퍼런스를 실측해서 씁니다. 기억이나 추측으로 수치를 쓰지 않습니다
3. 기존 캐릭터들의 락 10번 비교표에 새 캐릭터 열을 추가하고, 서로의 Negative에 이름과 포인트 컬러를 넣습니다
4. 이 README의 구조, 레퍼런스 표, 섞임 검사 항목에 추가

### 새 룩 추가 (예: 산타, 잠옷, 트렌치코트)

1. `characters/{캐릭터}/looks/{이름}.md` 생성
   - 상단에 락 우선 명시
   - 탈착 가능한 요소만 정의 (의상, 소품). 얼굴, 비율, 무늬, 귀, 꼬리는 건드리지 않음
   - 이 룩을 쓰지 말아야 할 상황도 함께 기재
2. `characters/{캐릭터}/references/3d_{이름}/`에 레퍼런스 이미지 추가
3. 이 README에 룩 판단 표 추가
